# Paper methods fact sheet

Scope: corrected AGX v7 experiment and corrected RP2040 v9/v10 campaign. This condenses the previously verified producing methods; it introduces no new experiments. In manuscript labels, lowercase **b** is the admission threshold and uppercase **B** is retained planning depth in the predecessor paper.

| Detail | Paper-ready specification |
|---|---|
| Mission and geometry | Four homogeneous logical robots on an obstacle-free, four-neighbor **19 x 19** grid (coordinates 0-18), starting at **(0,0), (0,6), (0,12), (0,18)**, all facing east. Complete all **50** distinct visit tasks: **eight initial and 42 online**. |
| Workload generation | Sample 50 distinct task cells uniformly without replacement from the 357 non-start cells. For each trace, generate 42 independent unit-exponential increments and scale by **lambda = 0.075, 0.30, 0.60 tasks/s** for low, medium, high load; release times are cumulative sums rounded to 9 decimals. Spatial layout and underlying arrival increments are paired across loads; policy/allocator arms reuse each trace. |
| Motion and service | Cardinal traversal **1.60 +/- 0.10 s** uniformly, clamped to 1.50-1.70 s; quarter-turn **0.30 s**; intent settling **0.10 s**; replan delay **0.30 s**. Common A* routing and collision-intent safety layer. Service has zero positive duration: complete a locally admitted known task on arrival or at a stationary safe boundary. Crossing an unreleased/unadmitted task cell does not complete it. |
| Communication | Lossless message delivery. AGX peer delay **40 +/- 10 ms** uniformly; RP2040 peer delay **40 ms**. Reliable environment-to-robot task announcements take **40 ms** in both. Robot allocation uses only local state and delivered messages. |
| Admission policies | All admit the initial eight together at time zero. **Eager:** admit each online task on release. **Count-b2/b4/b8:** release-order FIFO batches when pending count reaches **b = 2/4/8**. **Bounded-b4/W10:** Count-b4 plus a flush of the sub-four pending queue when its oldest task has waited **10 s**. The deadline bounds environmental queue residence, not completion latency. |
| Terminal residual | With no future releases, a pending sub-b batch may be admitted only after all previously admitted tasks have physically completed; this also applies to Bounded if earlier than its deadline. There is no automatic flush at final release. Successful Eager/Count-b2/b4/b8 have **43/22/12/7 total admission epochs**, including the initial epoch. |
| Retained state and allocators | Admission preserves current execution, ownership, and valid route state, with lightweight hooks at the next safe transaction. **CBAA:** one owned goal, retained winning bid during movement. **ACBBA:** marginal insertion and timestamped consensus, suffix release after ownership loss. **PI:** significance-based path repair/rescoring, valid executing head retained. **HIPC:** local team prediction and plan consensus, valid executing head/suffix retained. The three multi-task implementations have no planning-depth cap; the full eligible locally known task pool is available. Completion and local recovery hooks support online execution. |
| Timed transaction | FIFO decoded admission/peer/completion hooks, requested allocator-local recovery, and goal selection/repair/bidding. AGX measures elapsed **perf_counter_ns**; native MicroPython uses wrap-safe **ticks_us/ticks_diff**. Includes naturally triggered GC inside the transaction. Excludes serial transport, decoding, state restore/checkpointing, outbound extraction/serialization, logging, A* routing, and motion/control. This is elapsed allocator processor work, not total onboard computation. |
| Causal clock | Four independent virtual processors share one mission clock. Same-time calls freeze robot pre-states; measured duration makes the calling robot busy until virtual start plus duration. Releases, peers and messages continue, and incoming data buffer while busy. Outputs become visible at compute completion; a robot finishes an existing traversal before allocating. Physical serial execution of calls does not serialize the modeled robots. |
| Zero-compute treatment | Executes and measures the host allocator but inserts **zero** virtual compute duration. Outputs become available in zero-time microsteps. It can change the resulting execution trajectory; causal-minus-zero mission time is not a sum of removed call durations. |
| Design and retained outcomes | **50 independent trace blocks**, IDs 0000-0049, master seed **2026081406**, executed in two 25-trace rounds. Four allocators x three loads x five policies x 50 traces = **3,000** runs per AGX timing arm. Causal: **2,940 complete, 60 noncomplete**; zero-compute: **3,000 complete**. Keep the finite event/stagnation stopping-rule scope; do not infer permanent noncompletion. |
| RP2040 HIL | **96 planned jobs**: four allocators x three loads x two policies (Eager, Count-b4) x four traces (0000-0003); **82 successful, 14 terminal failures**, **38 complete paired blocks**. Four Pololu 3pi+ 2040 boards each execute a separate entire simulated four-robot mission using restored logical-robot checkpoints; movement and communication remain simulated. Every complete policy pair shares board and v9/v10 runtime lineage. |
| Outcomes and inference | Trace is the replicate. Continuous policy contrasts use common completed Eager/policy pairs; retain planned/completion denominators separately. Report paired mean absolute differences, percentage ratios of paired-cohort means, and median within-trace percentage changes with distinct labels. **10,000 shared trace-bootstrap draws**, seed **20260912**, resample the 50 trace IDs with replacement while retaining all paired outcomes and missingness; percentile **95% pointwise** intervals. Hardware summaries describe the tested pairs. Tasks and calls are not independent replicates. |

All-task latency is release-to-completion over 50 tasks; online-only latency uses 42. Per-trace p95 uses nearest rank (48th of 50). Work is summed measured duration of valid dispatched allocator transactions, including whole calls whose modeled completion can exceed the final task completion; it is not critical-path delay. Work/call divides work by calls within each trace before averaging; its cohort mean is not pooled work divided by pooled calls. Mission time is elapsed time to final task completion; team and maximum-robot steps count completed traversals. Logical allocation payload is pre-fan-out compact-JSON payload, not radio bytes.

Platform comparisons describe the tested native execution settings. Recorded operating conditions do not establish exact frequency/power settings or a controlled processor-speed experiment; these limits do not prevent reporting observed policy effects.
